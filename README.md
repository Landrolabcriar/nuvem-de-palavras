# Nuvem de Palavras Realtime

Nuvem colaborativa de palavras feita com HTML, CSS e JavaScript puro. A tela recebe novos registros pelo Supabase Realtime, mantém no máximo 80 palavras e remove cada palavra cerca de dois minutos após a criação.

## Arquivos

- `index.html`: interface, input e cliente Supabase via CDN.
- `style.css`: nuvem responsiva em tela cheia, com fundo escuro e palavras flutuantes.
- `script.js`: publicação, inscrição Realtime, repetição local e expiração dos registros.

## 1. Criar tabela, políticas e publicação Realtime

No Supabase, acesse **SQL Editor → New query**, cole e execute:

```sql
create table if not exists public.palavras_nuvem (
  id bigint generated by default as identity primary key,
  texto text not null,
  cor text,
  pos_x double precision,
  pos_y double precision,
  created_at timestamptz not null default now(),
  constraint palavras_nuvem_texto_tamanho check (
    char_length(trim(texto)) between 1 and 20
  ),
  constraint palavras_nuvem_pos_x_valid check (
    pos_x is null or pos_x between 0 and 100
  ),
  constraint palavras_nuvem_pos_y_valid check (
    pos_y is null or pos_y between 0 and 100
  )
);

alter table public.palavras_nuvem enable row level security;
grant select, insert on public.palavras_nuvem to anon, authenticated;
grant usage, select on sequence public.palavras_nuvem_id_seq to anon, authenticated;

drop policy if exists "Qualquer pessoa pode ler a nuvem" on public.palavras_nuvem;
create policy "Qualquer pessoa pode ler a nuvem"
  on public.palavras_nuvem for select
  to anon, authenticated
  using (true);

drop policy if exists "Qualquer pessoa pode inserir na nuvem" on public.palavras_nuvem;
create policy "Qualquer pessoa pode inserir na nuvem"
  on public.palavras_nuvem for insert
  to anon, authenticated
  with check (true);

do $$
begin
  alter publication supabase_realtime add table public.palavras_nuvem;
exception
  when duplicate_object then null;
end
$$;
```

As políticas públicas são adequadas apenas para teste: qualquer visitante pode ler e inserir palavras. Em produção, use autenticação e limite o `INSERT` ao papel `authenticated`. Nunca use a chave `service_role` no navegador.

Se a publicação `supabase_realtime` não existir no projeto, abra **Database → Publications**, habilite o Realtime e adicione `public.palavras_nuvem`. Se já estiver adicionada, o SQL acima não a adiciona novamente.

## 2. Configurar Supabase

No painel do projeto, acesse **Project Settings → API** (ou **Data API**) e copie **Project URL** e a chave pública **anon** ou **publishable**. Substitua `SUPABASE_URL` e `SUPABASE_ANON_KEY` no início de `script.js` caso use outro projeto. O arquivo contém os valores do projeto Supabase configurado nesta pasta; eles podem ser vistos no site, como toda chave pública. Não substitua pela chave `service_role`.

O cliente Supabase é carregado pelo CDN em `index.html`; o site não requer Node.js, dependências locais ou build.

## 3. Testar e publicar

Sirva a pasta localmente por HTTP (por exemplo, com a extensão Live Server no VS Code), abra em duas abas e aguarde **Conectado**. Envie uma palavra em uma aba; a inserção no Supabase entrega a palavra, cor e posição para as demais. A aba que publica também anima a resposta confirmada pelo banco.

Para publicar, envie `index.html`, `style.css`, `script.js` e `README.md` para a raiz do repositório GitHub e, em **Settings → Pages**, selecione **Deploy from a branch**, a branch principal e `/(root)`. O navegador precisa de internet para carregar o CDN e acessar o Supabase.

## Comportamento

- Palavras são normalizadas (espaços aparados, espaços repetidos reduzidos e letras minúsculas) e limitadas a 20 caracteres.
- Posição e cor são gravadas junto com cada palavra para que todos os clientes vejam a mesma nuvem.
- Repetir uma palavra já presente na tela aumenta seu tamanho e pulsa, sem uma nova gravação no banco. Essa repetição em memória é local à aba; novas palavras são sincronizadas pelo Realtime.
- Palavras expiram após dois minutos; a nuvem mantém no máximo 80 palavras.
